# New Observations

This file records issues discovered during Phase 2 remediation that were not part of the Phase 1 audit.
Per Hard Rule 1.1, new problems are NOT fixed silently; they are logged here for human review.

Format:
- `path:line`: One-line description (Suggested severity: HIGH/MEDIUM/LOW). Context and evidence.

---

- `backend/engine/artifacts.py:110` and `backend/engine/train.py:180`: Auxiliary artifact staging asymmetry (Suggested severity: MEDIUM). `primary_model.save(model_dir)` writes directly into `artifacts/<type>/model/` before `save_artifacts()` is invoked. When implementing atomic directory staging, auxiliary subdirectories created prior to `save_artifacts()` must be pre-populated from the existing directory into the temporary staging directory to prevent missing model files during atomic replacement.
- `backend/api/routes/metadata.py:286`: Private attribute access on search index (Suggested severity: MEDIUM). `get_item_detail` performed a linear scan over `ItemSearchIndex._entries` instead of using a public O(1) dictionary lookup method, risking `TypeError` if `_entries` was uninitialized. Resolved in F-019 by adding public `get_popularity_rank(item_id)` and `get_entry(item_id)` methods.
- `backend/tests/unit/test_config.py:101`: Trial schema assumption drift (Suggested severity: LOW). Unit test fixture assumed `trial["validation_metrics"]["eval_users"]` existed, whereas the canonical `tuning.json` schema generated by `tuning.py` stores `trial["evaluated_users"]` at the trial root.
- `backend/engine/articles_eval.py:425`: Missing explicit `logging` module import in module scope (Suggested severity: LOW). Invoking `logger.info` or calling logger methods inside `check_r2_no_leakage` required explicit logger module definition.
- `backend/discovery/datasets/mind.py:280`: Dict lookup pattern drift (Suggested severity: LOW). Multiple instances of `user_last_ts.get(uid, None)` flagged by Ruff lint `SIM910` in upstream/vendored adapter routines.
